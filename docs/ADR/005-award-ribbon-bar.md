# ADR-005: Отображение наград в виде орденской планки

**Статус:** Accepted  
**Дата:** 2026-09-17  
**Авторы:** EMH Team  
**Связанные ADR:** ADR-001 (Image Delivery)

## Контекст

В текущей реализации награды героя отображаются текстовым списком с бейджами (`hero__awards` в `<header>`). При большом количестве наград (> 10) список становится нечитабельным и занимает много места на странице.

Военная традиция и приказ Министра обороны РФ №1500 предписывают отображение наград в виде **орденских планок** — лент на металлической колодке, расположенных в порядке старшинства (от старших к младшим, слева направо, сверху вниз).

## Решение

### 1. Доменная модель

Справочник наград (`Award`) расширен полями:

| Поле | Тип | Назначение |
|------|-----|------------|
| `ribbon_image_url` | string | URL изображения ленты для планки (WebP) |
| `type` | AwardType | Тип награды: ORDER / MEDAL / BADGE |
| `jurisdiction` | AwardJurisdiction | Принадлежность: RUSSIAN_FEDERATION / USSR / DEPARTMENTAL |
| `worn_without_bar` | bool | Награда без колодки (звёзды орденов, знаки) |
| `is_jubilee` | bool | Юбилейная vs боевая (влияет на старшинство) |

Привязка награды (`HeroAward`) **денормализует** поля справочника, чтобы публичная
страница героя не выполняла второй запрос к каталогу (прецедент — `award_name`).
Денормализация заполняется JOIN'ом в `hero_award_repository.ListByHero`:

| Поле | Номер | Назначение |
|------|-------|------------|
| `ribbon_image_url` | 7 | URL ленты (пусто, если не загружена) |
| `type` | 8 | AwardType |
| `worn_without_bar` | 9 | Признак ношения без колодки |
| `is_jubilee` | 10 | Признак юбилейной награды |
| `jurisdiction` | 11 | AwardJurisdiction |
| `image_url` | 12 | URL знака награды (для текстового fallback) |
| `devices[]` | 6 | Знаки повторности — **вне текущего среза** (нет `UpdateHeroAwardRequest`) |

### 2. Логика сортировки (ГОСТ)

Приоритет отображения согласно приказу МО РФ №1500:

1. Ордена РФ (старшие → младшие)
2. Медали РФ (боевые → юбилейные, старшие → младшие)
3. Знаки отличия РФ
4. Ордена СССР
5. Медали СССР
6. Ведомственные знаки

Компаратор: `jurisdiction → type → is_jubilee → sort_order → name`
(реализован в `frontend/app/lib/awards.ts`, `compareAwards`).

> **Важно:** enum'ы приходят из protobuf-JSON строками (`"AWARD_TYPE_ORDER"`),
> поэтому ранги берутся из таблиц соответствия. Арифметика над строками
> (`a.type - b.type`) дала бы `NaN`. `HeroAward` не несёт `sort_order` — для
> привязок к герою эта ось пропускается, порядок внутри равных рангов сохраняет
> серверный `ORDER BY a.sort_order ASC` (стабильность `Array.sort`).

### 3. UX/Компонент

**Порог переключения:** планка рендерится, когда **ribbon-bearing** наград
(лента загружена и `worn_without_bar = false`) **больше 3**. Иначе — текстовый список.

**Компонент:** `frontend/app/components/heroes/AwardRibbonBar.vue` (авто-имя `<HeroesAwardRibbonBar>`).

**Поведение:** один `<Popover>` (PrimeVue 4, автоимпорт) по клику/тапу на кнопку
«Все награды» — одинаково на desktop и mobile. Внутри — **знак награды** (`image_url`)
и название. Компонента `<Tooltip>` в PrimeVue не существует (есть только директива
`v-tooltip`); разделение desktop/mobile через `useMediaQuery` не применяется —
единый механизм клика закрывает a11y (кнопка доступна с клавиатуры, `aria-expanded`/`aria-haspopup`).

**Группировка:**
- `worn_without_bar: false` и лента загружена → ленты на общей колодке (планка)
- остальные (без ленты или `worn_without_bar: true`) → только в текстовом fallback

### 4. Производительность

- `loading="lazy"` + `decoding="async"` на всех `<img>`
- Фиксированные `width`/`height` (36×12 планка, 144×48 знак) против CLS.
  `content-visibility: auto` **не применяется** к блоку планок: он в первом экране
  (`hero__opening`), где авто-скрытие вреднее скачка макета.
- Формат изображений: WebP (согласно ADR-001)
- **Один** rendition ленты (`ribbon_image_url`), масштабируется CSS'ом.
  Два rendition (36×12 / 144×48) и генерация thumbnail-воркером **отложены**
  до отдельной задачи пайплайна изображений (ADR-001 пока покрывает только Photo).

### 5. Размещение

Блок остаётся в `<header class="hero__opening">`. Логика порога — на уровне
страницы (`v-if="showRibbonBar"` → `<HeroesAwardRibbonBar>`, `v-else` → текстовый
`<ul class="hero__awards">`). Fallback-список показывает **все** награды героя
(включая `worn_without_bar` и награды без ленты), каждая со знаком `image_url`.

## Последствия

### ✅ Положительные
- **Аутентичность:** Уважение к военной традиции, соответствует ожиданиям пользователей (военные, историки)
- **Компактность:** 20+ наград умещаются в 2-3 ряда планок
- **Информативность:** Popover даёт доступ к детальной информации

### ❌ Отрицательные
- **Зависимость от данных:** Требуется качественный справочник наград (~400+ записей для РФ/СССР)
- **Сложность:** Реализация ГОСТ-сортировки требует тестирования
- **Производительность:** 20+ изображений на странице (решено через lazy load)

### ⚠️ Риски
- Отсутствие качественных изображений лент (нужен дизайнер/историк)
- Изменения в правилах ношения (приказ может обновиться)

## Альтернативы, которые не выбрали

| Альтернатива | Почему не выбрана |
|--------------|-------------------|
| Текстовый список с бейджами (текущее решение) | Не масштабируется при > 10 наградах |
| Полноценная 3D-модель формы | Избыточно, сложно в реализации |
| Только текстовый tooltip без изображений | Менее информативно |
| SVG-ленты | Нет качественных SVG для 400+ наград |

## Уточнения от 2026-09-17 (реализация)

Реализация внесла следующие уточнения в исходное решение:

- **Денормализация вместо клиентского join.** Публичная страница не тянет каталог
  `ListAwards`: поля справочника денормализованы в `HeroAward` (JOIN в
  `hero_award_repository.ListByHero`). Это убирает второй запрос и обходит
  известную несогласованность курсорной пагинации `ListAwards`.
- **Добавлена ось `jurisdiction`** (`AwardJurisdiction`: РФ / СССР / ведомственные),
  без неё порядок из приказа №1500 недостижим. Нулевое значение — `_UNSPECIFIED`
  (фактический стиль `enums_emh.proto`; правило `ENUM_ZERO_VALUE_SUFFIX` в `easyp.yaml` отключено).
- **Единый `<Popover>`** вместо связки `<Popover>`/`<Tooltip>` (последнего компонента нет в PrimeVue 4).
- **Порог** считается по ribbon-bearing наградам, а не по всем наградам героя.
- **Один rendition** ленты + CSS-масштаб; генерация thumbnail отложена.
- **`devices` вне среза:** нет `UpdateHeroAwardRequest`, а поле уже объявлено в proto.
  Валидация `count > 0` не добавлялась (мёртвый путь до реализации устройств).
- **Загрузка ленты** требует `UploadTypeAwardRibbon` в `domain` + записей в
  `allowedMIME`/`typePrefix` media-usecase; без них `GetUploadUrl` для лент
  возвращал `ErrUnsupportedUploadType`.
