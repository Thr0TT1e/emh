## 🎯 О проекте

Монорепозиторий проекта **«Вечная память героям»** — это открытая мемориальная платформа, посвящённая героям, не вернувшимся с поля боя. Мы собираем, систематизируем и сохраняем судьбы людей, погибших в глобальных и локальных конфликтах разных эпох. Проект объединяет:

- **Публичный мемориал** — поиск, фильтры, подробные карточки героев
- **Административную панель** — управление контентом, верификация данных
- **Краудсорсинг** — заявки от посетителей с модерацией
- **LLM-пайплайн** — автоматическое извлечение данных из текстов с human-in-the-loop
- **MCP-сервер** — интеграция с AI-ассистентами (Claude Desktop, Cursor)

Проект не имеет политической окраски — только дань памяти тем, кто отдал жизнь за Родину.

### Ключевые принципы

✅ **Достоверность** — каждая биография подтверждена минимум одним источником  
✅ **Уважение** — нейтральные формулировки, без политизации и сенсационализма  
✅ **Доступность** — открытый код, свободное использование данных  
✅ **Конфиденциальность** — защита персональных данных живых родственников

## 🚀 Возможности

### Для посетителей

- 🔍 **Поиск и фильтрация** — по ФИО, конфликтам, локациям, датам
- 📸 **Галереи фотографий** — с face-crop и превью
- 🗺️ **Интерактивные карты** — места рождения, боёв, захоронений (в разработке)
- 🏆 **Награды и звания** — информация о воинском пути
- 🔗 **Связи между героями** — родственники, сослуживцы, командиры
- 📱 **Адаптивный дизайн** — корректное отображение на всех устройствах (в разработке)

### Для администраторов

- ✏️ **Редактирование карточек** — с partial update через field_mask
- 🖼️ **Загрузка медиа** — presigned URLs в MinIO, автоматическая конвертация в WebP
- 🤖 **LLM-извлечение** — предзаполнение форм из сырого текста (статьи, посты) (в разработке)
- 📊 **Модерация заявок** — review workflow с аудитом
- 🔐 **Гибкая аутентификация** — JWT, API-ключи, rate limiting
- 📈 **Prometheus-метрики** — 40+ метрик для мониторинга

### Для разработчиков

- 🏗️ **Clean Architecture** — domain ← usecase ← delivery
- 🔄 **CQRS** — разделение команд и запросов
- 📦 **Connect RPC** — типобезопасный API поверх HTTP+JSON
- 🗄️ **UUIDv7** — монотонные ключи для курсорной пагинации
- ⚡ **ISR (Incremental Static Regeneration)** — быстрая отдача кэша с инвалидацией
- 🧪 **300+ тестов** — unit, integration, E2E

```
└────────────────────────┬────────────────────────────────────┘
                         │
         ┌───────────────┼───────────────┐
         ▼               ▼               ▼
┌─────────────┐  ┌──────────────┐  ┌──────────────┐
│  Frontend   │  │   Backend    │  │   MinIO      │
│  (Nuxt 4)   │  │  (Go API)    │  │  (S3)        │
│  :3000      │  │  :3480       │  │  :9000       │
└─────────────┘  └──────┬───────┘  └──────────────┘
                        │
                        ▼
                 ┌──────────────┐
                 │  PostgreSQL  │
                 │    :5432     │
                 └──────────────┘
```

### Слои Backend

```
┌─────────────────────────────────────┐
│  Delivery (Connect RPC серверы)     │ ← HTTP handlers, маппинг
├─────────────────────────────────────┤
│  UseCase (бизнес-логика)            │ ← оркестрация, валидация
├─────────────────────────────────────┤
│  Domain (сущности, интерфейсы)      │ ← чистый Go, без зависимостей
├─────────────────────────────────────┤
│  Repository (PostgreSQL)            │ ← SQL-запросы, транзакции
│  Storage (MinIO)                    │ ← S3-операции
└─────────────────────────────────────┘
```

**Ключевые паттерны:**
- **CQRS** для героя: `HeroUseCase` (команды) + `HeroQueryUseCase` (чтение)
- **Parallel loading**: `errgroup` для загрузки 6 связей в `GetHeroDetail`
- **LEFT JOIN LATERAL**: оптимизация N+1 в списках
- **Cursor pagination**: стабильная пагинация через композитные курсоры
- **Best effort**: удаление S3 не блокирует удаление из БД

## 🚀 Быстрый старт

### Требования

- Go 1.26.5+
- Node.js 22+
- Podman или Docker
- podman-compose
- Just (task runner)
- goose (SQL миграции)
- [easyp](https://easyp.tech/) (proto linting & generation)

### Backend

```bash
# 1. Клонирование репозитория
git clone https://codeberg.org/Thr0TT1e/emh.git
cd emh

# 2. Настройка окружения
cp infra/podman/.env.example infra/podman/.env
# Отредактируйте секреты: DATABASE_URL, MINIO_ROOT_USER/PASSWORD, AUTH_JWT_SECRET

# 3. Запуск инфраструктуры (PostgreSQL + MinIO)
podman-compose -f infra/podman/hmr/podman-compose-hmr.yml up -d

# 4. Применение миграций
just up

# 5. Генерация proto-кода
just gen-sdk

# 6. Запуск сервера
go run ./cmd/api
```

API будет доступен на `http://localhost:3480`.

### Frontend

```bash
cd ../frontend

# Установка зависимостей
pnpm install

# Запуск dev-сервера
pnpm dev
```

Frontend будет доступен на `http://localhost:3000`.
